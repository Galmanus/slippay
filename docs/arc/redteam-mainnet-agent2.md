# AgentVault red-team, Arc mainnet

The agent's session key is treated as stolen. Every attack below was run against the live vault
[`0x5316Aa47C7C8Ef468E6bc248184b0F35878772b8`](https://explorer.arc.io/address/0x5316Aa47C7C8Ef468E6bc248184b0F35878772b8) at block 26942496 (2026-10-20T12:22:59.000Z): an `eth_call`
simulation of `spend` from a random address, or a request through the production relayer. Nothing was
broadcast. Generated by `packages/arc-agent/scripts/arc-redteam.mjs`.

Session under attack: agent `0xE4C31bA5cEb9229A9dc365D15bc6d75c681565fF`, per-payment cap 0.20 USDC, window cap
0.30 USDC, every spend needs a fresh attestation from the integrity attester.

| Attack | Expected refusal | Observed | Result |
| --- | --- | --- | --- |
| stolen agent key pays the attacker | `RecipientNotAllowed` | `RecipientNotAllowed` | PASS |
| stolen agent key, one unit above the per-tx cap | `AmountExceedsCap` | `AmountExceedsCap` | PASS |
| stolen agent key, valid spend to the merchant, no attestation | `BadAttestation` | `BadAttestation` | PASS |
| stolen agent key, valid P-256 attestation from the attacker's own key | `BadAttestation` | `BadAttestation` | PASS |
| tampered amount on a validly signed request (relayer or MITM) | `BadSignature` | `BadSignature` | PASS |
| re-signed with a used nonce and a fresh deadline | `BadSignature` | `BadSignature` | PASS |
| deadline in the past | `Expired` | `Expired` | PASS |
| byte-for-byte replay of settled tx 0xf822f25c… | `BadSignature` | `BadSignature` | PASS |
| stolen agent key asks the production relayer to pay the attacker | `HTTP 403 attestation_refused` | `HTTP 403 attestation_refused` | PASS |
| stolen agent key asks the production relayer for more than the cap | `HTTP 403 attestation_refused` | `HTTP 403 attestation_refused` | PASS |

**10/10 refused as expected.**

What a stolen agent key cannot do here: pay anyone off the allowlist, exceed the per-payment cap, settle
without a fresh attestation from the session's attester, forge that attestation, or reuse an old signature.
The Foundry suite `contracts-evm/test/AgentVaultCompromise.t.sol` covers the stronger case where the
attester key is stolen too: the on-chain caps, allowlist, expiry and revocation still bound the loss.
